Interlock · Rule checks규칙 검증

Checking Interlock's rules against git and PythonInterlock 규칙을 git과 파이썬에 대어 보기

Interlock decides two things: whether an edit would make a merge conflict, and whether a call fits a function's signature. Both have an exact reference, git's own merge and Python itself. These checks generate random cases and compare Interlock's answer with the reference. Interlock이 판정하는 것은 두 가지입니다. 편집이 병합 충돌을 만드는지, 호출이 함수 시그니처에 맞는지. 둘 다 정답이 정해져 있습니다. git 자체의 병합과 파이썬 자체입니다. 이 검증은 무작위 사례를 만들어 Interlock의 답을 정답과 비교합니다.

Method방법

  • Conflict cases: random text files of 0 to 10 lines and random edits that replace a few lines. Lines come from a small set, so repeated lines make the alignment ambiguous, the hard case for a diff.충돌 사례: 0~10줄의 무작위 텍스트 파일과, 몇 줄을 바꾸는 무작위 편집. 줄을 작은 집합에서 뽑아 같은 줄이 반복되므로 정렬이 모호합니다. diff가 가장 틀리기 쉬운 경우입니다.
  • Call cases: random Python signatures and calls.호출 사례: 무작위 파이썬 시그니처와 호출.
  • Each check has a fixed random seed, so the same cases come out every run.검증마다 무작위 시드를 고정해 매번 같은 사례가 나옵니다.

What to watch주의할 점

  • Zero in 3,000 is not zero. With no disagreement in 3,000 cases, the disagreement rate is below about 0.1% at 95% confidence; it is not proven to be zero.3,000건 중 0건이 0은 아닙니다. 3,000건에서 불일치가 없으면, 불일치율은 95% 신뢰수준에서 약 0.1% 미만이라는 뜻이지 0으로 증명된 것은 아닙니다.
  • Small files. The cases are files of up to 10 lines. E4 tests the same rule on 5,352 real commit pairs.작은 파일. 사례는 10줄 이하 파일입니다. 같은 규칙을 실제 커밋 쌍 5,352개로 시험한 것이 E4입니다.
  • Python only. The call checks cover Python, not TypeScript.파이썬만. 호출 검증은 파이썬만 다루고 TypeScript는 다루지 않습니다.
