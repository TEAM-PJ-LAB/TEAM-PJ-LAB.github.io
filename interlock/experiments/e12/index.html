Interlock · Experiment E12실험 E12

Semantic conflicts, caught before the merge의미 충돌, 병합 전에 잡기

Most of what breaks parallel agents is not a merge conflict. One agent renames a record key or makes a function refuse a new case; another agent’s new code, written at the same time, still uses the old behaviour. Git merges both cleanly and the result is wrong. E12 measures how many of these Interlock catches while the agents work, on sets nobody had seen, against five targets we fixed before measuring.병렬 에이전트를 깨뜨리는 것은 대부분 병합 충돌이 아닙니다. 한 에이전트가 레코드 키 이름을 바꾸거나 함수가 새 경우를 거부하게 만드는 동안, 다른 에이전트가 같은 때 쓴 새 코드는 옛 동작을 그대로 씁니다. git은 둘을 깨끗이 합치지만 결과는 틀립니다. E12는 이런 충돌을 Interlock이 작업 중에 얼마나 잡는지, 아무도 본 적 없는 세트에서, 측정 전에 정한 다섯 목표로 잽니다.

How targets 1 and 2 are measured목표 1·2를 재는 방법

  • Units. Each task has a peer’s change, a correct integration and hidden checks. Claude Haiku 5.5 writes the other agent’s new code from the base code and a task sentence only, ten times per task. Each piece of new code is paired with its own peer change and, as a control, with an unrelated change from the same codebase.단위. 작업마다 동료의 변경, 올바른 통합, 숨은 검사가 있습니다. 다른 에이전트의 새 코드는 Claude Haiku 5.5가 기준 코드와 작업 문장만 보고 작업마다 열 번 씁니다. 새 코드마다 자기 작업의 동료 변경과 짝짓고, 대조로 같은 코드베이스의 무관한 변경과도 짝짓습니다.
  • Labels by execution. A unit is a conflict when the text merge succeeds and the merged code fails a hidden check, or when the merged code fails its own tests while each side alone passes (a test conflict, after Brun et al., FSE 2011). Units whose new code did not do its own task are dropped as invalid.실행으로 정한 라벨. 텍스트 병합이 되고 병합된 코드가 숨은 검사에 실패하거나, 병합된 코드가 자기 테스트에 실패하는데 양쪽은 각자 통과하면(테스트 충돌, Brun 외, FSE 2011) 충돌입니다. 새 코드가 제 작업을 하지 못한 단위는 무효로 뺍니다.
  • Replay without a model. Both agents’ edits go through Interlock’s real hooks in three orders (peer first, new code first, interleaved). A detection is any message claiming a conflict: a contract or effect finding, a merged test failing, or two runs of the new code answering differently (interference in the sense of Horwitz, Prins and Reps, 1989). A request to add a test is not counted either way.모델 없는 재생. 두 에이전트의 편집을 Interlock의 실제 훅에 세 가지 순서(동료 먼저, 새 코드 먼저, 번갈아)로 넣습니다. 충돌을 주장하는 메시지를 탐지로 셉니다. 계약·효과 발견, 병합한 테스트 실패, 새 코드를 두 번 돌린 결과가 다른 경우(Horwitz·Prins·Reps, 1989의 간섭)입니다. 테스트를 더 써 달라는 요청은 어느 쪽으로도 세지 않습니다.
  • Held out every round. Each round uses five new codebases, written by a separate session that did not read Interlock’s source; behaviour tasks are written by yet another session. Units are sealed before the replay, and until the verdict we look only at their counts. Lower bounds are one-sided 95% Clopper–Pearson.매 차수 처음 보는 세트. 차수마다 새 코드베이스 다섯 개를 Interlock 소스를 읽지 않은 별도 세션이 쓰고, 동작 작업은 또 다른 세션이 씁니다. 단위는 재생 전에 봉인하고 판정 전까지 개수만 봅니다. 하한은 단측 95% Clopper–Pearson입니다.
  • Interface covers record keys, return kind and size, exceptions, renames and signatures. Behaviour covers value meaning, constants, preconditions, side effects, defaults, None versus empty, and sort order.인터페이스는 레코드 키, 반환 종류·개수, 예외, 이름 변경, 시그니처입니다. 동작은 값의 의미, 상수, 전제 조건, 부작용, 기본값, None과 빈 값, 정렬 순서입니다.

Limits한계

  • Behaviour detection rests on running the merged tests. Without them, Interlock caught 2 of 243, 16 of 236 and 25 of 250 behavioural conflicts in rounds 22 to 24. A behavioural change that no test exposes is mostly missed: all 69 conflicts missed on round 24 were of that kind.동작 충돌 탐지는 병합한 테스트를 돌리는 데 기댑니다. 그것 없이는 22~24차에서 동작 충돌을 243개 중 2개, 236개 중 16개, 250개 중 25개 잡았습니다. 테스트로 드러나지 않는 동작 변경은 대부분 놓치며, 24차에서 놓친 69개가 모두 그런 경우였습니다.
  • Adding patterns one at a time generalised poorly. V3.23 caught 41 of the 52 conflicts missed on round 23’s set (now development data), but on round 24’s unseen set the rate without merged tests rose only from 0.068 to 0.100.모양을 하나씩 더하는 방식은 잘 일반화되지 않았습니다. V3.23은 23차 세트(이제 개발 데이터)에서 놓친 52개 중 41개를 잡았지만, 처음 보는 24차 세트에서 병합 테스트 없는 탐지율은 0.068에서 0.100으로만 올랐습니다.
  • The interface result does not depend on the tests. Without merged tests, interface recall was 0.980 (round 22), 0.990 (round 23) and 0.997 (round 24, lower bound 0.990), with no false alarm. Most of what the hidden-check-only definition calls false alarms are merges that break the agents’ own tests.인터페이스 결과는 테스트에 기대지 않습니다. 병합 테스트 없이도 인터페이스 재현율은 0.980(22차), 0.990(23차), 0.997(24차, 하한 0.990)이었고 오탐은 없었습니다. 숨은 검사만 보는 정의에서 오탐으로 잡히는 것은 대부분 병합이 에이전트 자신의 테스트를 깨뜨린 경우입니다.
  • Counting hidden-check failures only, round 24 meets neither target 1 (precision 0.966) nor target 2 (F1 0.776, precision 0.870); on round 23 the behaviour target was met that way (F1 0.826).숨은 검사 실패만 세면 24차는 목표 1(정밀도 0.966)도 목표 2(F1 0.776, 정밀도 0.870)도 미달입니다. 23차에서는 그렇게 세도 동작 목표는 달성이었습니다(F1 0.826).
  • All codebases are small Python projects written to our specification, sets M and N repeat the change kinds of E11’s sets P and O, separate machines are simulated on one, and each verdict was run once. Large real repositories, other languages and other agents were not measured.코드베이스는 모두 우리 명세로 쓴 작은 Python 프로젝트이고, 세트 M·N은 E11 세트 P·O와 같은 종류의 변경이며, 여러 기계는 한 기계에서 재현했고, 판정은 한 번씩 돌렸습니다. 실제 대형 저장소, 다른 언어, 다른 에이전트는 재지 않았습니다.
  • We build Interlock. The pre-registration commits, sealed units and raw data are in our private repository; the summary is published here.Interlock은 우리가 만든 도구입니다. 사전 등록 커밋, 봉인 단위, 원자료는 비공개 저장소에 있고, 여기에는 요약을 공개합니다.
