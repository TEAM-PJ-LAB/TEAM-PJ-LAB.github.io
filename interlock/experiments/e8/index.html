Interlock, Shepherd and Foremerge on the same tasks같은 작업에서 Interlock, Shepherd, Foremerge 비교

Shepherd and Foremerge also help AI coding agents coordinate. E8 runs all three tools, and no tool, on the same tasks with the same model and number of runs, each tool installed the way its makers describe. Shepherd와 Foremerge도 AI 코딩 에이전트의 조정을 돕는 도구입니다. E8은 세 도구와 도구 없음을 같은 작업, 같은 모델, 같은 횟수로 돌렸고, 각 도구는 제작자가 안내하는 방식 그대로 설치했습니다.

Method방법

  • Teammate: a script, not a model, stays alive for the whole run and tells each tool the same sentence in that tool's own way:동료: 모델이 아닌 스크립트가 시행 내내 살아 있으면서, 각 도구에 자기 방식으로 같은 문장을 알립니다.
    • Interlock: a claim and a declared signature (E8a), or the changed line range (E8b).Interlock: 점유와 선언된 시그니처(E8a), 또는 바뀐 줄 범위(E8b).
    • Shepherd: a work claim (intent and file globs) and an announce, kept alive by heartbeats.Shepherd: work 점유(의도와 파일 glob)와 announce. heartbeat로 살아 있음을 유지합니다.
    • Foremerge: agent register, intent publish (scope symbol:login=migrate, file:…=modify), work claim and start; in E8b also a ChangeSet.Foremerge: agent register, intent publish(scope symbol:login=migrate, file:…=modify), work claim와 start. E8b에서는 ChangeSet도 냅니다.
    • Shared note (no tool): the same sentence as a line in COORDINATION.md, and a CLAUDE.md rule in the agent's checkout to read that file before any task.공유 메모 (도구 없음): 같은 문장을 COORDINATION.md에 한 줄로 적고, 에이전트 체크아웃의 CLAUDE.md에 작업 전에 그 파일을 읽으라는 규칙을 넣었습니다.
  • Setup: each tool's own Claude Code setup, with MCP tools allowed for all three and a new HOME and repository for every run.설치: 각 도구의 Claude Code 설정을 그대로 썼습니다. 세 도구 모두 MCP 도구를 허용했고, 시행마다 새 HOME과 새 저장소를 썼습니다.
    • Interlock: what interlock init sets up (hooks, MCP server, AGENTS.md rules).Interlock: interlock init이 설치하는 것(훅, MCP 서버, AGENTS.md 규칙).
    • Shepherd: its user-scope MCP server, the SessionStart and PreToolUse hooks it installs on first connection (installed in advance), and .shepherd in the repository.Shepherd: user 범위 MCP 서버, 첫 연결 때 스스로 설치하는 SessionStart·PreToolUse 훅(미리 설치), 저장소의 .shepherd.
    • Foremerge: foremerge init, setup claude (MCP server and skill), checks set.Foremerge: foremerge init, setup claude(MCP 서버와 스킬), checks set.
  • One change in Shepherd's favor: HEARTBEAT_INTERVAL_SECONDS=5, a documented setting (default 60), so that its hook notices arrive even in short sessions.Shepherd에 유리하게 바꾼 것 하나: 문서화된 설정 HEARTBEAT_INTERVAL_SECONDS=5(기본 60초). 짧은 세션에서도 훅 알림이 전달되게 하려는 것입니다.
  • E8a: the four tasks of E1. The teammate is changing login(user, password) to login(user, password, otp).E8a: E1의 작업 4종. 동료가 login(user, password)를 login(user, password, otp)로 바꾸는 중입니다.
  • E8b: the same-line and far-apart edits of E2. The teammate has committed TIMEOUT = 60 on its branch, not yet merged.E8b: E2의 같은 줄 편집과 떨어진 줄 편집. 동료가 TIMEOUT = 60을 자기 브랜치에 커밋해 두었습니다(병합 전).
  • Judged by code: argument binding for calls, and git merge-tree for conflicts.판정은 코드가 합니다: 호출은 인자 바인딩, 충돌은 git merge-tree.

What to watch주의할 점

  • A notice that arrives is not enough here. Shepherd's hook delivered the news every time, but the agent followed the user's request and the code on disk, and put the warning in its report.여기서는 소식이 닿는 것만으로 부족했습니다. Shepherd의 훅은 매번 소식을 전했지만, 에이전트는 사용자 요청과 디스크의 현재 코드를 따르고 경고는 보고에만 적었습니다.
  • Interlock costs more. In E8a its runs took about twice the turns and 1.6 times the cost of runs with no tool, and it called its MCP tools in every run.Interlock은 비용이 더 듭니다. E8a에서 턴은 도구 없음의 약 2배, 비용은 1.6배였고, 매 시행 MCP 도구를 불렀습니다.
  • Refusing is not finishing. In E8b Interlock prevents the conflict by refusing the edit, so the change waits until the teammate's branch merges or someone decides.거부는 완료가 아닙니다. E8b에서 Interlock은 편집을 거부해 충돌을 막으므로, 그 변경은 동료 브랜치가 병합되거나 누군가 결정할 때까지 기다립니다.
  • The results match how both tools describe themselves: Shepherd's coordination is "advisory, never a gate", and Foremerge "never locks a file or blocks an agent".두 도구가 스스로 밝힌 설계와 같은 결과입니다. Shepherd는 조정이 "advisory, never a gate"라고, Foremerge는 "never locks a file or blocks an agent"라고 설명합니다.

Limits한계

  • Three runs per task, one model (Sonnet 5.5), and headless claude -p sessions only.작업마다 3회, 모델 하나(Sonnet 5.5), 헤드리스 claude -p 세션만 썼습니다.
  • The teammate is a script. We did not run an E6-style comparison with two live agents.동료는 스크립트입니다. 두 에이전트가 실제로 동시에 일하는 E6형 비교는 하지 않았습니다.
  • We chose Foremerge's operation (migrate) and the wording, and Shepherd's 5-second heartbeat. Interlock ran with its full setup (hooks, MCP and rules), unlike E1's hooks only.Foremerge의 연산(migrate)과 문장, Shepherd의 heartbeat 5초는 우리가 정했습니다. Interlock은 훅만 쓴 E1과 달리 MCP와 규칙까지 깐 전체 설정입니다.
  • The shared-note condition ran two days after the others, on Claude Code 2.1.304 instead of 2.1.303, not interleaved with them.공유 메모 조건은 다른 조건보다 이틀 뒤에, Claude Code 2.1.303 대신 2.1.304로 따로 돌렸습니다. 섞어 돌린 비교가 아닙니다.
  • Eight setup-check sessions (about $0.6) ran before the experiment and are not in the results.실험 전 설치 점검으로 8세션(약 $0.6)을 돌렸고, 결과에는 넣지 않았습니다.
  • We build Interlock. Every verdict is computed by code, and the raw data holds every tool call, hook output and final report. The Interlock source and the experiment harness are not public.Interlock은 우리가 만든 도구입니다. 판정은 모두 코드가 했고, 원자료에 모든 도구 호출, 훅 출력, 마지막 보고가 들어 있습니다. Interlock 소스와 실험 도구는 공개하지 않습니다.
