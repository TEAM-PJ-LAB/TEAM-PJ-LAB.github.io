Interlock · Experiment E11실험 E11

Interlock against Shepherd, pre-registeredInterlock 대 Shepherd, 사전 등록 비교

Real Claude Code agents work in parallel on a small codebase. We measure the share of tasks that end correctly merged and passing checks the agents never saw. Each time we changed Interlock after seeing results, we committed a new, unseen set of scenarios before running it. Earlier versions lost; the table shows every set.실제 Claude Code 에이전트들이 작은 코드베이스에서 동시에 일합니다. 끝까지 올바르게 병합되고 에이전트가 보지 못한 검사까지 통과한 작업의 비율을 잽니다. 결과를 보고 Interlock을 고칠 때마다, 실행 전에 처음 보는 시나리오를 새로 커밋(사전 등록)한 뒤 다시 쟀습니다. 이전 버전은 졌고, 표에 모든 세트를 실었습니다.

Where the gain comes from이득이 나오는 곳

The gain is concentrated in semantic conflicts: changes that merge cleanly as text but break another agent’s new code, such as a new required argument, a changed return type or a moved module (W1–W3). With Shepherd and no tool there was often no failed merge to repair, so the break reached main. On independent features and edits to the same function (W4, W5) all three conditions succeeded. Interlock catches the break before merging by sharing declared signatures and running tests on the state merged with teammates’ work.이득은 의미 충돌에 몰려 있습니다. 텍스트로는 깨끗이 병합되지만 다른 에이전트의 새 코드를 깨뜨리는 변경, 곧 필수 인자 추가, 반환 타입 변경, 모듈 이동(W1~W3)입니다. Shepherd와 도구 없음에서는 고칠 병합 실패가 없는 경우가 많아 깨진 채 main에 들어갔습니다. 독립 기능과 같은 함수 편집(W4, W5)에서는 세 조건 모두 성공했습니다. Interlock은 선언된 시그니처를 공유하고 동료 작업과 병합한 상태로 테스트해서, 병합 전에 깨짐을 잡습니다.

Limits한계

  • One model (Haiku 5.5). Sonnet, Opus, Codex, Cursor and OpenCode were not measured.모델은 Haiku 5.5 하나입니다. Sonnet, Opus, Codex, Cursor, OpenCode는 재지 않았습니다.
  • Small Python projects, six scenarios per set, 10 runs each. W uses the same six kinds of change as Y and Z (required argument, return type, rename or move, independent feature, same function, three agents) on a new codebase with new wording. Large refactors and other languages were not tested.작은 Python 프로젝트, 세트마다 시나리오 6개, 각 10회입니다. W는 Y·Z와 같은 여섯 종류의 변경(필수 인자, 반환 타입, 이름 변경·이동, 독립 기능, 같은 함수, 에이전트 3개)을 새 코드베이스와 새 문장으로 만든 것입니다. 대규모 리팩터링과 다른 언어는 재지 않았습니다.
  • Interlock’s per-turn time is still longer than Shepherd’s on W (4.6 s against 3.1 s); it finished sooner because it needed fewer turns and no conflict-resolution sessions.W에서도 Interlock의 턴당 시간(4.6초)은 Shepherd(3.1초)보다 깁니다. 턴 수가 적고 충돌 해결 세션이 없어 더 일찍 끝났습니다.
  • One conflict-resolution session per run was allowed, following the plan, which favors tools that do not block edits.계획서에 따라 시행마다 충돌 해결 세션 1회를 허용했고, 이는 편집을 막지 않는 도구에 유리하게 작용합니다.
  • Scoring is by script (merge result, pytest, hidden checks), with no blinded human review. The hidden checks are not published so that the scenarios stay usable.평가는 스크립트(병합 결과, pytest, 숨겨진 검사)이고 사람의 블라인드 리뷰는 하지 않았습니다. 시나리오를 계속 쓰기 위해 숨겨진 검사는 공개하지 않습니다.
  • We build Interlock. The pre-registration commits are in our private repository; the raw per-run data, Interlock source and harness are not public.Interlock은 우리가 만든 도구입니다. 사전 등록 커밋은 비공개 저장소에 있고, 시행별 원자료와 Interlock 소스, 실험 도구는 공개하지 않습니다.
