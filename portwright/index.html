Portwright by Team PJ — New Linux security fixes, for the kernels your devices actually ship. 기기에 실제로 들어간 오래된 리눅스 커널에, 새 보안 수정을.

Chip vendors freeze their Linux kernels at an old version, so every new security fix has to be ported by hand. Portwright uses AI to port each upstream fix to the vendor kernel, then checks it by building the patched kernel and booting it. 칩 제조사는 리눅스 커널을 오래된 버전에 고정해 두기 때문에, 새 보안 수정이 나올 때마다 사람이 직접 옮겨야 합니다. Portwright는 AI로 upstream 수정을 벤더 커널에 맞게 옮기고, 패치한 커널을 빌드하고 부팅해 검증합니다.

How it works작동 방식

Find the missing fix, port it, prove it builds and boots.빠진 수정을 찾고, 옮기고, 빌드 · 부팅으로 확인합니다.

An upstream patch that applies and compiles as published is checked and used as is. The AI only writes a backport when it does not.upstream 패치가 그대로 적용되고 컴파일되면 검사한 뒤 그대로 씁니다. 그렇지 않을 때만 AI가 백포트를 작성합니다.

  1. 01 · Find01 · 찾기

    List the fixes the vendor kernel is missing벤더 커널에 빠진 수정 목록

    Public kernel CVE data shows which security fixes reached the stable branch after the vendor froze its kernel.공개된 커널 CVE 데이터로, 벤더가 커널을 고정한 뒤 stable 브랜치에 들어간 보안 수정을 찾습니다.

  2. 02 · Port02 · 옮기기

    Rewrite the fix for the vendor code벤더 코드에 맞게 수정을 다시 작성

    An AI agent rewrites the upstream fix against the vendor tree. A separate critic agent reviews the draft and sends it back once if the fix is incomplete.AI 에이전트가 upstream 수정을 벤더 트리에 맞게 다시 작성합니다. 별도의 비판 에이전트가 초안을 검토하고, 수정이 불완전하면 한 번 되돌려 고치게 합니다.

  3. 03 · Check03 · 검증

    Apply, build, compare, boot적용 · 빌드 · 비교 · 부팅

    Each patch must apply and cross-compile for arm64 with no new warnings, and is compared with the upstream fix. Then all patches go in together, and the kernel has to boot in QEMU.패치마다 적용되고 arm64로 새 경고 없이 크로스 컴파일되어야 하며, upstream 수정과 비교합니다. 마지막으로 모든 패치를 함께 넣은 커널이 QEMU에서 부팅되어야 합니다.

Results실험 결과

Two rounds on one vendor kernel.벤더 커널 하나로 두 번 실험했습니다.

NXP linux-imx lf-5.15.y (based on 5.15.71), arm64, 40 fixes per round. The deciding round, R2, used fixes committed upstream after June 2026, after the model's training cutoff. Both rounds were pre-registered, and every change to the plan is logged.NXP linux-imx lf-5.15.y(5.15.71 기반), arm64, 라운드마다 수정 40건. 판정 라운드인 R2는 모델 학습 시점 이후인 2026년 6월 이후 upstream에 들어간 수정만 썼습니다. 두 라운드 모두 사전등록했고, 계획에서 바뀐 점은 모두 기록했습니다.

  • 15 / 15R2: fixes the upstream patch could not handle, ported, compiled and judged equivalent (95% interval 80–100%)R2: upstream 패치로 안 되던 수정을 옮겨 컴파일하고 동등 판정까지 통과 (95% 구간 80~100%)
  • 16 / 17R1: the same test on 2022–24 fixes, which the model may have seen in trainingR1: 모델이 학습 중 봤을 수 있는 2022~24년 수정으로 한 같은 실험
  • 40R2 fixes applied together; the patched kernel still boots in QEMUR2 수정 40건을 한꺼번에 넣은 커널도 QEMU에서 부팅
  • ~120kAI tokens per fix in R2, including the critic and the reviewR2 수정 1건당 AI 토큰 (비판 · 검토 포함)

The critic was the most useful step: in R2 it caught two incomplete drafts before scoring, and both were fixed in one revision. One of them matched the human stable backport line for line, so matching the human backport is not proof that a fix is right.가장 쓸모 있던 단계는 비판 에이전트였습니다. R2에서 채점 전에 불완전한 초안 2건을 잡아냈고, 두 건 모두 한 번의 수정으로 고쳐졌습니다. 그중 하나는 사람이 만든 stable 백포트와 한 줄도 다르지 않았습니다. 사람 백포트와 같다고 해서 맞는 수정이라는 증거가 되지는 않습니다.

Limits한계

What these numbers do not show.이 수치가 보여 주지 못하는 것.

Read the results as “the method works on this sample”, not “the patches are proven correct”.결과는 “이 표본에서 방법이 통한다”로 읽어야 하며, “패치가 맞다고 증명됐다”는 뜻이 아닙니다.

  • AI judging AIAI가 AI를 채점The author, the critic and the reviewers come from one model family, so their mistakes may line up. No human kernel engineer has reviewed the patches yet.작성 · 비판 · 검토를 모두 같은 계열 모델이 했기 때문에, 실수가 같은 방향으로 겹칠 수 있습니다. 사람 커널 엔지니어의 검토는 아직 받지 않았습니다.
  • Builds and boots is not fixed빌드 · 부팅 ≠ 해결Compiling and booting are the only checks that do not rely on AI. No exploit, KUnit or other runtime test has been run.AI에 기대지 않는 검사는 컴파일과 부팅뿐입니다. 공격 재현(PoC) · KUnit 같은 실행 시험은 아직 하지 않았습니다.
  • Small sample작은 표본One vendor tree, one architecture and 15 ported fixes in the deciding round.벤더 트리 하나, 아키텍처 하나, 판정 라운드에서 옮긴 수정 15건입니다.

Status현황

Where Portwright is todayPortwright의 현재

In development개발 중

Portwright is a research pipeline today, not a product you can use. Two rounds are done on one vendor kernel; the next step is a blind check by a human kernel engineer. Portwright는 지금 연구용 파이프라인 단계이며, 아직 쓸 수 있는 제품은 아닙니다. 벤더 커널 하나로 두 차례 실험을 마쳤고, 다음 단계는 사람 커널 엔지니어의 블라인드 검토입니다.

Built만든 것

  • A pipeline from a missing CVE fix to a patched kernel that boots, for NXP lf-5.15.y on arm64빠진 CVE 수정에서 부팅되는 패치 커널까지 이어지는 파이프라인 (NXP lf-5.15.y, arm64)
  • An independent critic step that reviews every AI backport before it is scored채점 전에 모든 AI 백포트를 검토하는 독립 비판 단계
  • Automatic gates: apply, arm64 compile with no new warnings, comparison with the upstream fix, QEMU boot자동 검사: 적용 · 새 경고 없는 arm64 컴파일 · upstream 수정과 비교 · QEMU 부팅
  • Pre-registered experiments whose numbers are all generated from committed files사전등록한 실험, 모든 수치는 커밋된 파일에서 자동 생성

Next다음 할 일

  • A third round on a second vendor or kernel line, such as a 6.1 BSP다른 벤더나 커널 버전(예: 6.1 BSP)으로 3차 실험
  • Runtime tests beyond compile and boot컴파일 · 부팅을 넘어선 실행 시험
