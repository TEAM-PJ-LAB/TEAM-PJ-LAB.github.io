Interlock by Team PJ — Stop your AI coding agents from overwriting each other. AI 코딩 에이전트끼리 서로의 작업을 덮어쓰지 않게.

Interlock lets a team run Claude Code, Codex and Cursor on the same repository at the same time. It tracks what every agent is changing, holds edits that would collide, and explains every decision. Interlock은 Claude Code, Codex, Cursor를 한 저장소에서 동시에 돌릴 수 있게 합니다. 에이전트마다 무엇을 바꾸는지 추적하고, 부딪힐 편집은 잡아 두며, 모든 판단의 근거를 보여줍니다.

How it works작동 방식

A signal box for your agents.에이전트를 위한 신호소.

Interlock installs as an MCP server and a GitHub App next to the agents you already use. Every change passes three gates, so even an agent that never asks gets stopped. Interlock은 쓰던 에이전트 옆에 MCP 서버와 GitHub App으로 설치됩니다. 모든 변경이 세 관문을 지나므로, 묻지 않는 에이전트도 막힙니다.

  1. Gate 1 · Edit관문 1 · 편집

    Before the edit lands편집이 들어가기 전

    Hooks for Claude Code, Codex and Cursor check every edit. Claims are per function, so two agents can work in the same file.Claude Code·Codex·Cursor 편집 훅이 모든 편집을 확인합니다. 점유는 함수 단위라 두 에이전트가 같은 파일에서 일할 수 있습니다.

  2. Gate 2 · Commit관문 2 · 커밋

    Before the commit커밋하기 전

    A git pre-commit hook catches anything that slipped past the editor.편집 단계를 빠져나간 변경은 git pre-commit 훅이 잡습니다.

  3. Gate 3 · Merge관문 3 · 병합

    Before mainmain에 합치기 전

    A GitHub merge check keeps colliding branches out of main.GitHub 머지 체크가 충돌하는 브랜치를 main 밖에 둡니다.

  • No deadlocks교착 없음A fair queue with cycle detection.공정한 대기열과 순환 감지.
  • No stale locks남는 잠금 없음Claims expire when a session dies.세션이 끝나면 점유가 자동 해제됩니다.
  • Every verdict explained모든 판단에 근거Who holds what, on which branch — and what's free instead.누가 무엇을 어느 브랜치에서 잡고 있는지, 대신 쓸 수 있는 부분까지.

Status현황

Where Interlock is todayInterlock의 현재

Pre-release정식 출시 전

Interlock works end to end in our own experiments and runs as hooks, an MCP server and a GitHub App next to the agents you already use. It is not generally available yet, and a few limits are worth knowing before you try it. Interlock은 자체 실험에서 처음부터 끝까지 작동하며, 쓰던 에이전트 옆에 훅 · MCP 서버 · GitHub App으로 붙습니다. 아직 정식 출시 전이고, 써 보기 전에 알아 둘 한계가 몇 가지 있습니다.

Works today지금 되는 것

  • Function-level claims, enforced at the edit, the commit and the merge함수 단위 점유, 편집 · 커밋 · 머지 단계에서 차단
  • Calls checked against a teammate's declared signature, with the reason for every refusal동료가 선언한 시그니처에 맞춰 호출 검사, 모든 거부에 이유 제공
  • Tested with live Claude Code sessions on small Python projects작은 Python 프로젝트에서 실제 Claude Code 세션으로 검증
  • Hook answers in about 3 to 6 ms on a 2,000-line file2,000줄 파일에서 훅 응답 약 3~6 ms

Limits today지금의 한계

  • Signature checks cover Python, not TypeScript시그니처 검사는 Python만 지원하고 TypeScript는 아직입니다
  • Codex and Cursor hooks are not yet run with live agentsCodex · Cursor 훅은 아직 실제 에이전트로 돌려 보지 않았습니다
  • It refuses a colliding edit instead of resolving it, so that task waits for a person or the other branch충돌할 편집은 해결하지 않고 거부하므로, 그 작업은 사람이나 상대 브랜치를 기다립니다
  • Coordination costs extra turns and tokens, and hooks slow down on files of 5,000+ lines조정에 턴과 토큰이 더 들고, 5,000줄 이상 파일에서는 훅이 느려집니다

Method, limits and raw data for every experiment실험별 방법 · 한계 · 원자료
